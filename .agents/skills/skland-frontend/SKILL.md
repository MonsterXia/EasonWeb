# 森空岛前端数据、资源与 UI

## 使用入口与核对状态

明日方舟数据页面的现有 UI 已由用户核对，作为后续维护基准；终末地 UI 尚未由用户核对，不能把共享组件或合成测试通过当作其展示已确认。

修复森空岛 UI 时，先应用下节通用设计原则；涉及明日方舟资料排版、指标卡、设施、横幅、生息演算或展开交互时，再读 [明日方舟 UI 风格](references/arknights-ui.md)。该文档集中维护布局、尺寸、透明图标、主题与动效；资源来源和调参保留在 [资源说明](references/assets.md)，字段含义和公式保留在 [显示规则](../easonweb-development/references/skland-data.md)。方舟专属规则不自动推广到终末地。

## 森空岛通用 UI 设计

以下原则从用户已核对的明日方舟 UI 提炼，作为森空岛后续 UI 修复的默认方向，可用于终末地的通用呈现修复。它们不确认终末地的业务语义、分组方式或专属布局；方舟的九项日常、六项基建、固定列数、无千分位及模式图案属于专属规则，使用时查阅对应章节。

- **紧凑但完整。** 采用细边框、轻底色、小圆角，标签／主数值／辅助说明分层且以左对齐为主；通过缩减内边距和冗余行提高密度，完整保留名称、时间、单位和状态，长文本换行增高。不要用省略号、固定高度裁切或缩写大数换取整齐。
- **按信息关系组织。** 简单资料用标签／数值行，摘要用紧凑指标卡，设施内的多个指标共用设施容器，头像与姓名／等级组成身份卡；模式记录按官方素材结构安排横幅。避免每个数字一张卡、图标单占一行和多层卡片嵌套。同组同类卡片对齐标题、数值和底部说明。
- **官方图片与透明装饰。** 已有官方素材优先，通用操作和方向箭头才用 Element Plus 图标。分组标题图标、头像和水印优先透明底；水印放卡片右侧、降低透明度且不拦截点击，不抢占内容行。空状态的圆角图标底板不自动套到游戏图标；确需底板的图片容器才使用主题表面色。
- **主题服务于数据。** 复用 `--color-background*`、`--color-border`、`--color-heading`、`--color-text`、`--muted`、`--accent`；浅色浅底深字，深色暗底浅字。单色官方图由 `OverviewArtwork.vue` 按素材元数据适配，彩色图片保留原色；警告、成功、稀有度和模式语义色不统一染粉。普通指标不因数值突出而另造高亮底色。
- **图片不决定数据布局。** 缺图、加载中或失败时保留文字、占位与对齐，沿现有资源链兜底。背景与前景标识有不同语义时分别渲染、分别处理失败；遮罩仅保护文字对比，不能遮掉素材纹理。裁切位置依据实际图片内容，不能把方舟的 58% 起点或半幅裁切套给所有横幅。
- **状态真实。** 0、缺失、未知上限、已完成和局部失败分别表达，保留真实超上限数值。进度条只用于已核实的比例语义，不为装饰补造百分比；当前紧凑摘要指标沿用无进度条样式。数字分隔和单位按游戏／字段规则决定，不从某张方舟卡片推广到所有数据。
- **窄屏保留信息关系。** 根据内容调整列宽与换行，不把空状态的手机纵排套到所有数据网格。成对指标、徽章和连续分区按各自规范保留结构，检查 320px／390px、长中文和英文均无横向溢出；具体列数由游戏专属规范或后续核对决定。
- **折叠与刷新稳定。** 分组复用原生 `details/summary`，展开动画复用 `OverviewReveal.vue`／`animatedDetails.ts`，支持连续反向切换、减少动态效果和卸载清理，隐藏项不可聚焦。轻量展开按钮保持透明背景、文字交互态和可见键盘焦点。局部刷新保留身份、选择和工具栏，骨架只替换数据区；局部错误不遮掉仍可用内容。

### 用本 skill 修复 UI

先定位问题所属组件和游戏，再区分通用呈现问题、偏离已核对细则的问题、尚待核对的专属设计。明日方舟优先恢复下方参考文档的基准；终末地可修复通用间距、对齐、透明图标、主题、溢出与交互问题，但不直接复制方舟指标数量、数据公式或模式布局，也不把“现有源码如此”当作用户已确认。

沿 `SklandPage.vue → GameOverviewPanel.vue → OverviewLiveDetails.vue` 定位，共享图片看 `OverviewArtwork.vue`／`OperatorAvatar.vue`，记录横幅看 `OverviewRecords.vue`。先复用现有组件和样式，字段来源不清时阅读显示规则；若专属布局需要新依据，再对照用户提供的核对结果或已验证的官方展示。改共享样式时检查两个游戏，交付中区分实际验证结果与仍待用户核对的终末地部分。

## 数据与状态

- 通过 `GET /game/hypergryph/account/overview` 读取已绑定角色，查询参数为 `appCode`、`uid`、`gameId`；Cookie 身份由后端校验，客户端不传第三方凭证。角色唯一键同时包含这三个字段。
- 账号列表通过 `src/common/gameAccountOrder.ts` 稳定排序：明日方舟优先、终末地其次，未知游戏排后；同游戏保持上游角色顺序。首次打开默认选第一个角色，刷新时保留仍存在的已选角色，不修改缓存原数组。
- 森空岛定位为游戏小工具集合，首页入口使用“小工具”，角色资料、日常进度与签到是并列能力，不将入口写成“前往签到”。
- `src/common/sklandCache.ts` 在内存中缓存角色列表和概览 5 分钟，以网站用户 ID、鹰角手机号和绑定更新时间隔离；概览键包含 appCode/gameId/uid。进入页面仍重新校验当前网站身份；不将角色数据或凭证写入持久存储。
- 切换角色命中缓存时立即展示；复用同角色正在进行的请求，版本号阻止旧结果覆盖新选择。切换不取消其他角色的加载，完成后可供返回时复用；卸载取消未完成请求、保留已完成缓存。刷新账号清空缓存，刷新角色资料只强制更新选中角色。登录/注册/密码重置、退出及绑定变更成功后清空缓存；失败不清空。
- 资料加载与签到保持独立状态。选中项、标题及刷新按钮原位保留，骨架仅替换数据内容。缓存与身份失效的回归在 `tests/skland-cache.test.js`、`tests/api.test.js`。
- `GameOverview` 是后端整理后的展示契约。`updatedAt` 表示上游游戏记录时间，`fetchedAt` 表示本次读取时间，均为秒；`calculatedAt` 是上游计算时钟。不得把读取时间冒充同步时间。明日方舟理智、无人机仅按后端已核实的 `recovery` 基线在内存中随时间更新（`resourceRecovery.ts`），保持五分钟缓存、禁止每秒轮询；终末地仅显示上游 `curStamina`，不可套用方舟的六分钟规则。
- 两个游戏的字段与公式来源见 [森空岛显示规则](../easonweb-development/references/skland-data.md)。设施、探索、活动使用可折叠分组；零上限探索显示横线。办公室可刷新状态与精确刷新次数分开，干员档案数（含形态）与去重收藏数分开。新增字段须同步后端 OpenAPI、中英文和边界回归。
- 数字 `0` 是有效值，`null` 显示缺失状态；日常与基建紧凑指标卡不显示进度条；其他已有进度条仅在当前值存在、上限大于 0 时展示。允许理智超上限，文字保留真实值，已有进度条最多填满。
- 方舟基建概况沿用官方六项名称与顺序：无人机、休息进度、订单进度、制造进度、干员疲劳、线索收集。`overviewMetrics.ts` 复用会客室详情 `arknightsClues.items[id=board]` 的 current/total 补齐线索卡（不是 own 库存），缺失保留 null，不增加请求、不修改缓存。使用已有 `ak-icon-meeting` 官方图标；规则仅用于方舟，未知指标保留在后。
- 方舟日常状态固定展示官方九项和顺序，由 `dailyStatus.ts` 复用现有计数与详情生成训练室、公招刷新等状态卡；说明与倒计时规则见显示规则文档。保全采用用户确认的每月16日北京时间04:00实际刷新时间。
- 收藏与养成、日常、基建和干员档案的布局见 UI 风格文档。终末地 `profile.level` 显示权限等阶，`worldLevel` 显示探索等级；这是字段约定，不代表终末地 UI 已核对。干员与任务名称保留游戏原文，其余词条与日期格式同步中英文。
- 干员头像按官方来源解析：方舟由 `operatorAvatars.ts` 优先根据后端 `skinId` 生成官方 `char_skin/avatar` 地址，缺失或加载失败回退 charId 默认头像（转职阿米娅默认使用 #2 皮肤头像），最后姓名首字；干员档案和助战的 skinId 均从账号 chars 按 charId 获取，不能从持有皮肤列表或助战独立字段猜测；终末地优先使用概览 `operators[].avatarUrl`，由后端从已有 charData.avatarSqUrl / avatarRtUrl 选择。不再使用前端 ID/MD5/管理员形象映射、本地 PNG 或头像目录同步。终末地缺图或加载失败只显示姓名首字文字兜底，不猜测默认头像。来源见 [头像说明](../../../src/assets/game-avatars/README.md)。不新增逐干员取图接口或后端图片代理。
- 概览的日常、基建、收藏、地区与模式图使用 `src/assets/skland/` 的本地资源及 `overviewAssets.ts` 稳定 ID 映射；来源与 SHA-256 见该目录 README / sources.json。新增资源先核对官方语义，未知地区/活动不猜图。条目优先使用已核实、随概览返回的官方 `artworkUrl`，本地条目图和通用图依次兜底；具体字段来源与 CDN 约束见资源说明。通过 `OverviewArtwork.vue` 保持尺寸、懒加载、原色及加载失败回退；不得新增后端图片代理或运行时目录同步。提交前运行 `npm run overview-assets:check`，更新资源使用显式 `overview-assets:sync`。
- `OperatorAvatar.vue` 用于干员档案和助战头像，容器背景透明、不加底色；固定图片占位、懒加载，并在缺失或加载失败时显示文字兜底；更换 URL 后重置失败状态。不得以首字母头像替代已有可用图像。静态链接/图片更新经过审查后随前端发布，不在运行时自动同步。
- 上游字段与来源见 CommonServerAPI 的项目 skill；不要从签到响应推导资源或伪造资料。浏览器验证至少包含角色切换的响应竞态、缺失值、局部失败恢复及刷新时工具栏可见。

## 查资料与新增字段

先阅读 [两游戏显示规则](../easonweb-development/references/skland-data.md)，按游戏分别核对上游字段、官方 formatter 与页面条件，再对照用户录屏的标签和单位。录屏是显示证据，不包含可复用的私有账号数据。固定版本模块可能过期；新规则记录来源链接、日期和未核实部分。不要凭名称、等级或相近字段推断规则。

数据有误时沿 `SklandPage → gameOverviewAPI → CommonServerAPI normalizeGameOverview` 追踪，先区分上游快照、后端计算、前端计时与缓存。特别是方舟主线的精确空字符串代表全部完成，null 仍是未提供。新字段需同步后端模型/OpenAPI、前端 `GameOverview`、中英文词条及边界用例。

## 图片从哪里拿

按 [资源获取与主题适配](references/assets.md) 选择来源与同步方式。现有脚本和清单是唯一同步入口，构建和页面运行不下载目录。不要为此复制一个独立同步脚本。

## 验证与交付

启动项目与选择后端参照 [本地运行与后端对接](../easonweb-development/references/local-debugging.md)。森空岛横幅调参、明暗主题及布局验证见本 skill 的 [横幅调参与验证](references/assets.md#横幅调参与验证)。

- 数据、排序或交互修改：`npm test`、`npm run build`。测试用合成数据覆盖缺失/零值/已完成、两个游戏、中英文与缓存切换；不要提交真实响应、录屏、凭证。
- 资源修改：额外执行 `npm run overview-assets:check`，核对清单、图片哈希、Vite 构建产物；在浅色、深色和手机宽度检查图标/文字对比度、加载失败兜底。
- UI 验证保留工具栏；检查首次默认角色、手动切换、刷新后的选择、竞态与错误恢复。签到、短信、解绑不是只读验证步骤。
- 发布后用真实页面读取角色检查文案和资源，必要时确认当前页面加载的脚本哈希；旧页面不一定已载入新版本。前端构建或合成测试不证明生产账号已正确显示。
- 项目通用主题、国际化与部署约定见 [EasonWeb 开发 skill](../easonweb-development/SKILL.md)。中间计划留在仓库外。
