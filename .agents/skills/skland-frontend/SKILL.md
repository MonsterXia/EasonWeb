# 森空岛前端数据与资源

- 通过 `GET /game/hypergryph/account/overview` 读取已绑定角色，查询参数为 `appCode`、`uid`、`gameId`；Cookie 身份由后端校验，客户端不传第三方凭证。角色唯一键同时包含这三个字段。
- 账号列表通过 `src/common/gameAccountOrder.ts` 稳定排序：明日方舟优先、终末地其次，未知游戏排后；同游戏保持上游角色顺序。首次打开默认选第一个角色，刷新时保留仍存在的已选角色，不修改缓存原数组。
- 森空岛定位为游戏小工具集合，首页入口使用“小工具”，角色资料、日常进度与签到是并列能力，不将入口写成“前往签到”。
- `src/common/sklandCache.ts` 在内存中缓存角色列表和概览 5 分钟，以网站用户 ID、鹰角手机号和绑定更新时间隔离；概览键包含 appCode/gameId/uid。进入页面仍重新校验当前网站身份；不将角色数据或凭证写入持久存储。
- 切换角色命中缓存时立即展示；复用同角色正在进行的请求，版本号阻止旧结果覆盖新选择。切换不取消其他角色的加载，完成后可供返回时复用；卸载取消未完成请求、保留已完成缓存。刷新账号清空缓存，刷新角色资料只强制更新选中角色。登录/注册/密码重置、退出及绑定变更成功后清空缓存；失败不清空。
- 资料加载与签到保持独立状态。选中项、标题及刷新按钮原位保留，骨架仅替换数据内容。缓存与身份失效的回归在 `tests/skland-cache.test.js`、`tests/api.test.js`。
- `GameOverview` 是后端整理后的展示契约。`updatedAt` 表示上游游戏记录时间，`fetchedAt` 表示本次读取时间，均为秒；`calculatedAt` 是上游计算时钟。不得把读取时间冒充同步时间。明日方舟理智、无人机仅按后端已核实的 `recovery` 基线在内存中随时间更新（`resourceRecovery.ts`），保持五分钟缓存、禁止每秒轮询；终末地仅显示上游 `curStamina`，不可套用方舟的六分钟规则。
- 两个游戏的字段与公式来源见 [森空岛显示规则](../easonweb-development/references/skland-data.md)。设施、探索、活动使用可折叠分组；零上限探索显示横线。办公室可刷新状态与精确刷新次数分开，干员档案数（含形态）与去重收藏数分开。新增字段须同步后端 OpenAPI、中英文和边界回归。
- 数字 `0` 是有效值，`null` 显示缺失状态；进度条仅在当前值存在、上限大于 0 时展示。允许理智超上限，文字保留真实值，进度条最多填满。
- 角色概览按日常、基建、收藏和干员档案分组；终末地 `profile.level` 显示权限等阶，`worldLevel` 显示探索等级。干员与任务名称保留游戏原文，其余词条与日期格式同步中英文。
- 干员头像按官方来源解析：方舟由 `operatorAvatars.ts` 根据 charId 和官方 CDN 规则生成地址（转职阿米娅使用 #2 皮肤头像）；终末地优先使用概览 `operators[].avatarUrl`，由后端从已有 charData.avatarSqUrl / avatarRtUrl 选择。不再使用前端 ID/MD5/管理员形象映射、本地 PNG 或头像目录同步。终末地缺图或加载失败只显示姓名首字文字兜底，不猜测默认头像。来源见 [头像说明](../../../src/assets/game-avatars/README.md)。不新增逐干员取图接口或后端图片代理。
- 概览的日常、基建、收藏、地区与模式图使用 `src/assets/skland/` 的本地资源及 `overviewAssets.ts` 稳定 ID 映射；来源与 SHA-256 见该目录 README / sources.json。新增资源先核对官方语义，未知地区/活动不猜图。条目优先使用已核实、随概览返回的官方 `artworkUrl`，本地条目图和通用图依次兜底；具体字段来源与 CDN 约束见资源说明。通过 `OverviewArtwork.vue` 保持尺寸、懒加载、原色及加载失败回退；不得新增后端图片代理或运行时目录同步。提交前运行 `npm run overview-assets:check`，更新资源使用显式 `overview-assets:sync`。
- `OperatorAvatar.vue` 固定图片占位、懒加载，并在缺失或加载失败时显示文字兜底；更换 URL 后重置失败状态。不得以首字母头像替代已有可用图像。静态链接/图片更新经过审查后随前端发布，不在运行时自动同步。
- 上游字段与来源见 CommonServerAPI 的项目 skill；不要从签到响应推导资源或伪造资料。浏览器验证至少包含角色切换的响应竞态、缺失值、局部失败恢复及刷新时工具栏可见。

## 查资料与新增字段

先阅读 [两游戏显示规则](../easonweb-development/references/skland-data.md)，按游戏分别核对上游字段、官方 formatter 与页面条件，再对照用户录屏的标签和单位。录屏是显示证据，不包含可复用的私有账号数据。固定版本模块可能过期；新规则记录来源链接、日期和未核实部分。不要凭名称、等级或相近字段推断规则。

数据有误时沿 `SklandPage → gameOverviewAPI → CommonServerAPI normalizeGameOverview` 追踪，先区分上游快照、后端计算、前端计时与缓存。特别是方舟主线的精确空字符串代表全部完成，null 仍是未提供。新字段需同步后端模型/OpenAPI、前端 `GameOverview`、中英文词条及边界用例。

- 方舟活动、集成战略、保全、剿灭和引航者试炼使用 `OverviewRecords.vue` 的单层横幅卡，参照官方手机端将名称/期数与成绩横向叠放在背景上；标识只占左侧 60–76px，常规行高约 64–72px，不能再把左半张卡片留空。五类横幅铺满整卡并共用语义主题底色、文字色与渐变遮罩保证可读，不用浓主题底色遮掉纹理；引航者试炼采用更窄的自适应网格（列宽起点 280px、卡片不超过 340px），只显示横幅左半部以裁掉无纹理的尾部，左侧独立叠加官方 logo；浅色主题用浅底、清晰可见的原色纹理（明暗主题共用 `--skland-banner-opacity`，默认 1；渐变遮罩仅保护文字对比，不再单独覆盖各模式图片不透明度）、深色字及深色单色 logo，深色主题保留暗底白字白色 logo。期数标签用淡主题色底和主题色字，不使用深色实心底。长标题自然增高且背景跟随，缺图回到主题底色与图标，保持行布局。引航者试炼第一行名称与右侧期数标签，第二行最高进度左对齐；按已核实期数数值降序，未知期数保留在末尾；在前端副本排序，不修改缓存。生息演算使用 `SandboxDetails.vue` 的生存日、见证及里程碑分区，不能退回只显示名称的通用卡片。集成战略收藏品和投资由 `overviewSections.ts` 按主题 ID 合并为单个分组和卡片，共用整张横幅，名称与两项数据移至右侧无图案区域（约从横幅 58% 处起），左侧原图保持可见，不能拆为独立图片区或把文字压在左侧图案上；明暗主题使用各自底色、文字与右侧渐变遮罩。两项值独立保留零值和缺失，不按数组位置配对，不修改缓存原数据。专属字段规则见上述显示规则文档，回归在 `tests/e2e/overview-records.spec.ts`。

保全派驻的设施 logo 与背景必须同时、独立渲染：背景用接口 `artworkUrl`，前景按官方设施 ID 规则取图，各自处理失败；图标不能仅作为背景兜底。保全与引航者试炼共用明暗主题遮罩：浅色为浅底深字、深色单色 logo，深色为暗底白字、白色 logo；背景保持原色，不透明度由共享参数控制，单色 logo 沿用共享主题规则（包括缺图兜底），不得在浅色页面强制黑底白标。

剿灭作战同样独立渲染背景与关卡标志：前景按 `campaign/zone_icon/{encodeURIComponent(id)}.png` 官方规则解析，通用模式图只在该图标失败时兜底；各关卡标志不能被共用背景替代。明暗主题与保全保持一致。每条记录使用接口返回的独立 `artworkUrl`（上游 infoMap.picUrl）；即使背景外观相似也不能合并为固定共用图或保存本地默认背景。背景与 logo 各自加载和兜底。

SideStory 与别传沿用集成战略的横幅右侧布局：保留整张官方背景，名称、通关进度及完成状态置于右侧无图案区域，保护左侧图片内嵌标题；共用 `banner-end-record` 样式，适配明暗主题及长标题。背景以 cover 等比铺满、左对齐裁切；窄屏和文字换行增高时也必须贴合上下边缘，禁止 contain 造成留白。无图、加载中或失败均保留同一右侧文字起点（58%），名称、进度与状态和有图卡片对齐；左侧显示兜底图标，不因图片状态切回紧凑文字布局。

## 验证与交付

启动项目与选择后端参照 [本地运行与后端对接](../easonweb-development/references/local-debugging.md)。森空岛横幅调参、明暗主题及布局验证见本 skill 的 [横幅调参与验证](references/assets.md#横幅调参与验证)。

- 数据、排序或交互修改：`npm test`、`npm run build`。测试用合成数据覆盖缺失/零值/已完成、两个游戏、中英文与缓存切换；不要提交真实响应、录屏、凭证。
- 资源修改：额外执行 `npm run overview-assets:check`，核对清单、图片哈希、Vite 构建产物；在浅色、深色和手机宽度检查图标/文字对比度、加载失败兜底。
- UI 验证保留工具栏；检查首次默认角色、手动切换、刷新后的选择、竞态与错误恢复。签到、短信、解绑不是只读验证步骤。
- 发布后用真实页面读取角色检查文案和资源，必要时确认当前页面加载的脚本哈希；旧页面不一定已载入新版本。前端构建或合成测试不证明生产账号已正确显示。
- 项目通用主题、国际化与部署约定见 [EasonWeb 开发 skill](../easonweb-development/SKILL.md)。中间计划留在仓库外。
