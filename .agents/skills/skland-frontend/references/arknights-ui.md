# 明日方舟数据 UI 风格

维护森空岛明日方舟的资料、指标、设施、模式记录和展开交互时读取。明日方舟数据页面的现有 UI 已由用户核对，本规范以该 UI 为维护基准，并于 2026-10-05 对照工作区组件整理。终末地的模块规范另见 [终末地参考](endfield-ui.md)；共享组件或测试通过不代表新增设计已获用户确认。路径相对仓库根目录；尺寸是当前实现基准，调整时以源码和浏览器效果为准。

全站配色、页面标题、空状态仍遵循 [通用 UI 规范](../../easonweb-development/references/ui-design.md)；字段含义、顺序和计算见 [两游戏显示规则](../../easonweb-development/references/skland-data.md)，图片来源、同步与横幅调参见 [资源说明](assets.md)。方舟专属布局与字段规则不自动套用到终末地。

## 视觉与信息层级

- 以紧凑、左对齐、易扫读的数据布局为主：细边框、轻底色、小圆角，标题／数值／说明形成层级。靠缩减间距提高密度，保留完整名称、日期和状态，长文本自然换行增高。
- 沿用樱花粉语义主题，表面和文字使用 `--color-background*`、`--color-border`、`--color-heading`、`--color-text`、`--muted`。理智与其他指标共用底色、边框和数字色；游戏模式中的黄／红、成功／警告等语义色保留，不统一染粉。
- 资料区、日常状态、基建概况、详情分组、干员档案保持各自层级。收藏与养成紧接基础资料、位于日常之前，复用 `GameOverviewPanel.vue` 的 `profile-facts` 标签／数值行；不另起一组大卡片。无收藏数据不留空行。
- 收藏标签旁保留 `metricArt` 的 18px 官方图标，透明底，数字与标签文字对齐。数字 0、缺失横线与可选上限分别保留。干员与任务名称保留游戏原文，其他标签、状态与日期格式同步中英文。
- 分组标题官方图标、收藏图标、干员头像与右侧水印均使用透明背景。通用组件的图标底板不是每张游戏图都要加的装饰。头像复用 `OperatorAvatar.vue`，已有官方图优先，加载失败按业务规则回退，保留固定占位。
- `OverviewArtwork.vue` 依据 `tone` 区分单色和彩色：单色图适配浅色深墨／深色浅墨，彩色原图保留色彩，不对整组图片统一反色。装饰不拦截点击，邻近已有同义文字的图片不重复朗读。

## 标题与整组折叠

2026-10-05 用户明确要求标题文字及图标与官方对齐：明日方舟使用“实时数据”“基建数据”“我的干员”，不再显示“日常状态”“基建概况”“干员档案”作为这三处分组标题。前两项使用官方透明标题条中的独立图标区域；我的干员使用官方 CharSkinList 的 Pn SVG 原始路径（ArknightsOperatorsIcon.vue），不能用收藏统计的 ak-char 或通用图标替代。词条位于 arknightsTitles，仅用于方舟；英文实时／基建采用官方 TIMING DATA／BASE DATA，干员译为 My Operators。

同日用户确认：实时数据、基建数据、我的干员三组标题均使用原生 details/summary 与 vAnimatedDetails，共享三角及 260ms 动画，初始展开。切换角色重新默认展开，同角色更新不强制展开手动收起的分组。实时数据内部仍保留两行与更多，干员仍保留搜索与展开全部；搜索及更多位于折叠内容内，不放进 summary。

这三组的折叠外观与公开招募等详情栏目一致：每组顶部 1px 主题分隔线、上下各 18px 内边距，无额外组间 margin；标题 15px／600、图标使用 28px 占位与 8px 右间距，透明底。后续设施区去掉重复的 30px 顶部间距，我的干员同样使用分隔线。不能仅加折叠箭头而保留旧标题块的独立留白。

标题细调（2026-10-05 用户截图）：三组新增官方图标保留 28px 布局占位，图形统一 scale(0.6)，使实际轮廓约 15–17px，与公开招募等栏目相当，不能通过缩小占位移动标题文字。方舟 details.operator-section 后的 snapshot-note 去掉旧 30px margin-top，使用栏目自身的 18px 底部内边距，避免收起后多出一行空白。

## 日常与基建指标

入口为 `OverviewLiveDetails.vue` 的 `compact-metrics`，两组都不显示进度条。

| 项目 | 桌面基准 | 手机（≤600px） |
| --- | --- | --- |
| 网格 | 最小列宽 160px，按容器自动排布 | 固定双列 |
| 间距／内边距／圆角 | 8px／10px 12px／8px | 6px／9px 10px／8px |
| 右侧图标水印 | 64px、透明底、opacity 0.14 | 56px，保持低透明度 |
| 文字层级 | 标题、主数值、底部说明；数字 23px，文字型状态 16px | 保持层级，允许换行 |

- 组内卡片等高，标题与数值顶部对齐，说明放独立末行并统一底边距离。图标融入右侧背景，不独占行；不靠省略号、固定高度裁切或隐藏恢复时间提高密度。
- 日常和基建数字不加千位分隔，完整保留预计回满日期。缺失、真实零值、超上限各自展示，不将未知上限猜为 0 或 100%。
- 日常默认最多两行，按实际列数计算可见数量；超过两行才有展开／收起，切换角色恢复折叠。基建在组内始终显示全部指标，没有内部“更多”按钮；外层“基建数据”标题仍可折叠整组。方舟日常九项与基建六项的名称、顺序由 `dailyStatus.ts`、`overviewMetrics.ts` 及显示规则维护，不按卡片宽度删项。

## 设施与助战

详情分组保留原生 `details/summary`、透明标题图标和折叠控制。按内容选择现有布局：

| 内容 | 组件／样式 | 布局规则 |
| --- | --- | --- |
| 贸易站、宿舍、制造站 | `compact-facility-grid` + `base-facility-grid` | 名称与等级首行，状态与计数同排且数量标签紧邻数值，完整时间独占底行；右侧淡水印。最小列宽 200px，内边距 10px 12px、行距 6px、卡间距 8px，窄屏自然换行 |
| 公开招募槽位 | `recruitment-grid` | 位置与状态左对齐，右侧官方公招图水印，完整完成时间可换行；桌面最小列宽 160px，手机双列 |
| 办公室与训练室 | `paired-facility` | 两者同时存在时共用一个标题和折叠控制，按“办公室图标 办公室 与 训练室图标 训练室”排列；两张卡在窄屏仍双列，各自保留等级、名称、状态和时间 |
| 会客室与线索 | `ReceptionDetails.vue` | 一个设施、一张卡；标题不显示指标条目数。卡内四项指标宽屏四列、窄屏两列，共用右侧淡图，不再给每项加底板 |
| 助战干员 | `support-grid` | 40px 头像在左，姓名与等级在右侧上下排列；内边距 10px、卡间距 8px、最小列宽 150px，窄屏自然换行，保留完整姓名 |

会客室的等级、状态和完成时间只取 `id=board`；线索搜集、自有、收到、待领取按 `board/own/received/needReceive` 稳定 ID 映射，不能把四项指标画成四个房间或按数组位置匹配。缺失为横线，零值保留，未知上限不推测。其他详情继续占满分组所在行，不因办公室双列而全局改成双列。

## 模式记录横幅

使用 `OverviewRecords.vue` 的单层横幅卡：背景铺满整卡，文字叠在背景上，不拆成图片区和上下信息栏。常规最小行高桌面 72px、手机 64px，长标题可增高，背景同步覆盖上下边缘。按素材结构选择文字起点：

| 类型 | 文字与图像布局 |
| --- | --- |
| 保全派驻、剿灭作战 | 左侧仅预留桌面 76px／手机 60px 标识位，其余区域横排名称与成绩。背景与前景设施／关卡 logo 同时独立渲染、独立失败兜底；logo 不是只在缺背景时才显示 |
| 引航者试炼 | 左侧独立官方 logo，名称与期数在第一行，最高进度在第二行左对齐。网格列宽起点 280px、卡片不超过 340px；背景容器宽 200% 并从左裁切，仅此模式裁去无纹理的右半部 |
| SideStory／别传、集成战略 | `banner-end-record` 的文字统一从约 58% 起，保护左侧原图内嵌标题；加载中、缺图、失败也保留相同起点，左侧显示兜底图标。保留整张背景，不采用试炼的半幅裁切 |

- 背景使用 `cover` 等比铺满、左对齐裁切，不能用 `contain` 留白。左右布局在手机保留，不能以固定高度截断长标题。
- 浅色采用浅主题底、深字和深色单色 logo，深色用暗底、浅字和浅色单色 logo；彩色横幅保持原色。共享 `--skland-banner-opacity`（当前 1）与 `--skland-banner-scrim-opacity`（当前 0.75），默认值在 `src/assets/base.css`。渐变遮罩保护文字对比，不能用浓底色盖住纹理；不在各模式或主题中单独覆盖背景不透明度。变量不影响文字、独立 logo 与兜底图。
- 期数标签使用淡主题底与主题色字；活动完成状态使用主题主色，浅色主题不能继承暗色横幅的浅粉文字。引航者试炼按已核实期数数值降序，未知排后；对副本排序，不改变缓存。
- 集成战略当前是各主题摘要横幅，没有独立的主题选择器或逐关详情组件；外层分组默认折叠。收藏品／投资由 `overviewSections.ts` 按主题 ID 合并成同一分组和卡片，两项值独立保留 0 与缺失；不能按数组位置配对或拆成重复横幅。
- 剿灭每条记录保留自己的接口 `artworkUrl`，不因背景相似改成共用固定图。保全、剿灭前景使用已核实的官方 ID 图标规则，失败再用通用模式图；来源和具体 URL 规则见 [资源说明](assets.md#横幅与模式标识)。

## 生息演算

使用 `SandboxDetails.vue` 和 `SandboxMilestones.vue` 的专用结构，不退回只有名称的通用记录卡。

- 外层 `.sandbox-card` 的模式图标以透明装饰放在右上角，不独占一行；名称桌面 20px、手机 18px，预留图标空间，保留分组 summary 图标和折叠控制。
- 生存日为相连双列，常规渐变半环、险途红色半环；半环是装饰，不是百分比进度，不猜上限。两种模式的数字后方复用 `day-common` 中的中央徽记，险途通过 CSS 转红，光晕单独用径向渐变；保留边缘渐隐，避免强化 `day-challenge` 自带光晕或硬圆形裁剪产生色斑。徽记、半环与翻译文本独立，不以章节勾号代替徽记。
- 天数不加千位分隔，零与缺失分别显示；缺失时单位隐藏但保留占位，双列说明对齐。
- 见证三幕保留官方独立徽章与完成叠层，以 `mainQuest >= chapter` 判断完成；缺失单独处理。手机仍为三列、无独立卡片底板，保留完整标题及完成／未完成／缺失文本；支线为紧凑状态列表。
- 里程碑为连续双列分区：驻地跨左侧两行，探索与抵御敌袭在右侧上下排列，陌域探访和固定委托在底部。复用 `logoBase/logoExplore/logoResist/logoRecord`，不拆为五张独立圆角卡；替换资源时同步来源清单和 SHA。
- 里程碑大数不加千位分隔、不缩写，0 与缺失横线分别保留。深色黄／红强调数字，浅色深金／深红，辅助文字用 `--muted`；彩色素材只按既有规则调亮度保证对比。320px 下仍保留相同分区，说明换行增高，不能固定高度裁内容。

## 我的干员

档案主体在 `GameOverviewPanel.vue`，方舟条目使用头像加文字，不套用终末地单干员 details 或潜能角标。文字顺序为姓名、稀有度／潜能、职业／属性（有值才显示）、等级／精英化阶段；保留完整姓名和已装备皮肤头像。`operators=null` 为资料缺失，空数组为无条目；档案数包含额外形态，不替换资料区去重收藏数。

名称搜索不区分大小写，去掉首尾空白；无搜索时初始显示 8 项，展开全部后可收起，搜索结果全显。当前实现监听 data 对象替换重置搜索与内部展开，不将“同角色保留整组折叠”误解为搜索也保留。语言切换不替换 data，不应丢失搜索。档案头像回归在 `tests/e2e/operator-avatars.spec.ts`；`operator-archive.spec.ts` 专测终末地，不能作为方舟独有布局已覆盖的依据。

## 展开与收起

- 日常网格和干员列表复用 `OverviewReveal.vue` 的 260ms 高度过渡；收起的隐藏项保持 `aria-hidden` 和 `inert`，不可聚焦。无搜索时，干员收起动画完成后只保留首 8 项；搜索结果不按此数量截断。
- 展开按钮 hover／active 仅改变文字颜色，透明背景、无阴影和按压位移，禁用文本选择与触摸高亮；键盘焦点以文字下划线清晰提示，日常展开按钮保留 `aria-expanded`／`aria-controls`。
- 详情分组复用 `src/common/animatedDetails.ts`，要求直接子元素 `:scope > summary` 与 `:scope > .facility-content`；缺任一项指令不安装。保留原生 summary 键盘行为；只裁剪 `.facility-content` 高度到 0，不把分组内边距计入。保留末帧直到原生 details 关闭，避免收起闪烁。
- `vAnimatedDetails` 将最新展开意图写入 `data-details-expanded`，三角由 `src/common/animatedDetails.css` 随该属性旋转，不能只按原生 `[open]`（收起动画结束才变化）判定。指令支持连续反向切换，卸载移除事件和动画；宽度／子项高度测量由 `OverviewReveal` 的 ResizeObserver 承担，普通 details 指令自身没有观察器。
- `OverviewReveal` 的插槽首个元素作为测量容器，收起高度取前 visibleCount 个直接子项底边的最大值；visibleCount=0 用于完整隐藏详情。组件只负责高度与 collapsed 事件，调用方给隐藏项设置 `aria-hidden`／`inert`。干员收起事件完成后才释放多余节点，减少动态效果或高度未变化时也发出 collapsed；`prefers-reduced-motion` 下取消过渡，内容和可访问性状态仍正确。
