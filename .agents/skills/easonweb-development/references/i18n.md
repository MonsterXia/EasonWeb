# 国际化约定

修改页面文案、错误提示、主题菜单、语言切换或新增语言时使用本规范。当前支持简体中文 `zh-CN` 和英文 `en`，采用 Vue I18n Composition API。路径相对仓库根目录。

## 实现入口

- `src/i18n/index.ts`：全局 i18n、`tr()`、语言偏好、持久化及浏览器事件同步。
- `src/i18n/preferences.ts`：语言类型与纯函数 `resolveLocale()`。
- `src/i18n/shell.ts`、`home.ts`、`accounts.ts`、`games.ts`：按模块组织的 `zhCN` / `en` 词条；注册命名空间分别为 `shell`、`home`、`account`、`game`；`overview.ts`、`checkIn.ts` 通过 games.ts 合入 `game.overview`／`game.skland.attendance`。
- `src/components/Navigator.vue`：简体中文、English、跟随系统菜单。
- `src/App.vue`：随当前语言切换 Element Plus locale；`src/main.ts` 在挂载前调用 `startLocaleSync()`。
- `src/router/routes.ts`：页面的 `titleKey` / `descriptionKey`；`main.ts` 将当前路由 meta 交给 `startLocaleSync()`，新增页面的元信息也须有双语词条。
- `src/composables/useOverviewFormat.ts`：按 locale 缓存 Intl 数字、日期与时间格式器；角色概览的 Unix 秒转毫秒统一在此处理，不在每次时钟 tick 重建格式器。
- `tests/i18n.test.js`：语言选择规则、词条对齐与编译、插值参数、元信息及存储/事件同步测试。

## 新增或修改文案

1. 在对应模块的两种语言中同时新增语义化 key。不要使用序号或把完整中文句子作为一般界面 key。
2. Vue 组件在 setup 中使用 `const { t } = useI18n()`，模板绑定 `t('namespace.key')`。组件之外使用 `tr()`，不要在模块初始化时缓存翻译后的字符串。
3. 标题、按钮、表单 label、placeholder、aria-label、确认/取消、空状态、错误/成功提示都需要翻译。`EmptyState` 的 title/description 由调用页传入翻译值；该组件不持有业务词条。
4. 含动态数据的句子使用命名插值，例如 `t('account.resendIn', { seconds: remaining })`；避免用片段拼接语序。计数、金额与日期按所选 locale 格式化，不让数字格式参与业务判断。
5. 一般文案不含 HTML，不用 `v-html` 渲染翻译。Vue I18n 对 `@`、花括号、管道符有特殊语法；用合法 literal interpolation 或改写示例，运行词条编译测试确认。
6. 保留品牌标识、语言自称（简体中文 / English）、用户昵称与第三方原始内容；不要把外部字符串当作翻译 key 或自动翻译后写回服务器。

## 切换行为

- `eason-locale` 只保存 `zh-CN`、`en` 或 `system`。显式选择优先；跟随系统按 `navigator.languages` 中首个支持的语言解析 `zh-*` / `en-*`；均不支持时回退中文。坏值按跟随系统处理。
- 使用 `setLocalePreference()` 切换，不能另建页面级 locale 状态或手工修改 DOM 文本。存储不可用时仍应在当前标签页生效。
- 跨标签页的 storage 变化（含清空存储）、系统语言变化均需同步。系统语言变化不能覆盖显式语言选择。
- 同步 `<html lang>`、文档标题、description 和 Element Plus 内置提示；不要只翻译业务页而遗漏下拉框、标签关闭或确认按钮。
- 切换不刷新路由、不重建整页、不清空输入、倒计时、武器清单或推荐结果。反馈文案从消息 key/参数或原始错误响应计算，切换时更新为当前语言。
- 持续提示参考 AuthPage / AccountBindings 的函数加 computed，以及 SklandPage 的原始错误加 computed；`userPage.vue` 当前退出失败用短暂 ElMessage，在切换语言时关闭。修改提示行为时区分这两种实现，不宣称已有 toast 会原位重译。

## 游戏数据与错误边界

- `weapons.ts` 的中文名称与属性是当前匹配用的规范值；仅翻译显示层，严禁用英文显示值替换比较、Map key、选项 value 或 API 参数。
- 英文版武器/地区名暂保留国服名称，页面有明确说明；属性与技能标签是描述性翻译，不宣称为官方英文术语。新增官方名称映射须核实来源，并保留稳定标识。
- 昵称、UID、奖励名称及旧版签到文本保留原文。结构化签到的 status/errorCode 使用 `checkIn.ts` 本地词条，不直接显示原始码或从上游文本推断状态；日期随 locale 格式化。HTTP 错误类别与本地校验通过 `apiError` / `passwordError` 使用词条；没有英文对照的中文后端错误在英文界面使用本地通用提示。不按翻译后的报错文本分支业务逻辑。
- 终末地描述中的 `<@...>` / `</>` 强调标记通过 `src/common/endfieldText.ts` 的 `endfieldPlainText()` 去除，保留文字和换行；它不是通用 HTML 清洗器，结果仍按 Vue 文本插值显示，不送入 `v-html`。回归见 `tests/endfield-text.test.js`。

## 验证与维护

- 运行 `npm test` 和 `npm run build`；两种词条 key 和命名插值参数必须一致，所有消息可编译。新增状态反馈要验证已有提示随语言切换，不能悄悄丢掉。
- 浏览器检查首页、认证、用户资料、鹰角绑定、森空岛与计算器；覆盖中英文、刷新保持偏好、Element Plus 内置提示及元信息。
- 用较长英文检查桌面与手机布局：菜单不挤压品牌、按钮不截断、表单可读、无横向溢出。验证语言切换后输入与武器选择仍在，推荐与删除逻辑不变。
- 新增第三种语言需同步类型/解析规则、messages 注册、菜单、Element Plus locale 及测试，不仅新增一个词条文件。
## 游戏区服名称

角色区服通过 `src/common/gameServers.ts` 展示，优先使用 API 的 `serverName`：明日方舟来自 `channelName`，终末地来自角色的 `serverName`。官服 / B服等通用名称走词条，其他上游专有名称原样保留。旧响应缺字段时只对已核实的明日方舟渠道 `1 → 官服` 回退，其他值显示“未知区服（编号）”，不要把终末地 `serverId` 套用成渠道编号。该显示逻辑不得修改签到请求的原始 ID。

依据：[森空岛绑定响应样例](https://github.com/ProbiusOfficial/Skland_API#森空岛app)、[终末地 PlayerRole 字段](https://pkg.go.dev/github.com/starudream/sign-task/pkg/skland/api#PlayerRole)。
